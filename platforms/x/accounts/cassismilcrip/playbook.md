# @cassismilcrip 運用プラン（x-algorithm ベース）

[@_cassis_milk](https://x.com/_cassis_milk) の配信切り抜きアカウント [@cassismilcrip](https://x.com/cassismilcrip) を伸ばすための運用プラン。
根拠は submodule の [`x-algorithm`](../../x-algorithm/)（2026-11-07 時点、commit `3b6919f`）。

> **注意:** リポジトリ内の数値はコード上のデフォルト値。本番では設定システムで上書きされることがあり、一部のルール（botmaker の一部、Grox プロンプト）は非公開。
> そのため「この通りにすれば必ず伸びる」ではなく「コード上こう動く」という前提で使う。

## 1. 「シャドウバン」の正体

x-algorithm に「shadowban」という名前のラベルはない。実体は **アカウントや投稿に付くラベルによって、フォロワー以外へのおすすめから外れること**。

- フォロー中アカウントの投稿は `TimelineHome`、フォロー外（おすすめ）の投稿は `TimelineHomeRecommendations` という別ルールで判定される
  （`home-mixer/candidate_hydrators/vf_candidate_hydrator.rs:92-106`）
- おすすめ側だけに追加で適用されるアカウントラベル（`visibility-filtering/rules/levels.rs:65-72`）:
  `SpamHighRecall` / `Compromised` / `ReadOnly` / `ImpersonationHighPrecision` / `AbusiveHighRecall` / `DoNotAmplify`
- 投稿ラベル: `SPAM_HIGH_RECALL` / `DO_NOT_AMPLIFY` / `MALICIOUS_URL`、および著作権（DMCA）メディア（`levels.rs:147-152, 348`）

→ **フォロワーには見えるが、フォロー外の「おすすめ」には一切出ない**。これが「シャドウバンされている」と感じる状態。

### ラベルの有効期限（多くは自然に外れる）

| ラベル | 付く条件（コード上） | 期間 |
| --- | --- | --- |
| `SpamHighRecall`（アカウント） | 固定ポストに低品質/危険URL（`botmaker-rules/scarecrow/bot/PinnedLowQualityOrBadUrl.bot`） | 7日 |
| `SpamHighRecall`（アカウント） | スパムスコア系（`abuse-enforcement-service/service-lib/rules/enforcement_user.yaml`） | 7日 / 30日 |
| `AgathaSpamTopUser`（アカウント） | ブロック・スパム報告が「フォロー外からのいいね」に比べて多い | 7日 |
| `RISKY_HIGH_VIZ_REPLY`（リプライ） | 他人のスレッドへのスパム的リプライ（Grox 判定） | 14日 / 30日 |
| `SPAM_HIGH_RECALL`（投稿） | 速すぎる大量リプライ・意味のない文など | 30日（一部は無期限） |

## 2. まずやること：原因の特定

1. **Under the Hood は新規アカウントでは使えない**
   - 表示条件は「**アカウント作成から1年以上**」かつ「**前月に10件以上投稿**」（`under-the-hood/strato/columns/underTheHoodReport.User.strato:18-22, 683-689`）
   - レポートは月単位で、月末から10日以上経ってから出る（同 `minDaysAfterMonthEnd = 10`）
   - → @cassismilcrip が使えるのは**作成1年後**。それまでは下の方法で状態を推測する
   - （参考：@kkk4oru が条件を満たしていれば、個人アカウント側のラベルは確認できる）
2. **フォローしていないアカウントから見えるか確かめる**
   - フォロー中の人のタイムラインと、フォロー外への「おすすめ」は別のルールで判定される。ラベルで弾かれるのは「おすすめ」側だけ
   - @kkk4oru は @cassismilcrip をフォローすると「フォロー中」扱いになるので、確認には使えない
   - 友人など**フォローしていない人**に、その人の「おすすめ」や投稿画面で見えるか確かめてもらう
3. **インプレッション数の推移を見る**
   - インプレッションがほぼフォロワー数の範囲から伸びない状態が続くなら、「おすすめ」に出ていない可能性が高い
   - 投稿ごとのインプレッションを `analytics/` に記録して比較する
   - 検索結果・リプライ欄の表示判定はこのリポジトリに含まれていないので、コードからは判断できない
4. **DMCA（著作権）通知が来ていないか確認する**（メール・通知）
   - DMCA 対象の投稿はおすすめから外れ、表示されてもメディアが再生できなくなる（`visibility-filtering/rules/tweet_rules.rs:884-889`）
   - 正当な理由がある場合のみ異議申し立てが可能 → https://help.x.com/forms/ipi/dmca-counternotice
5. **固定ポストのリンクを確認する**
   - 短縮URLや評判の悪いドメインへのリンクを固定していると、アカウントごと 7 日間 `SpamHighRecall` が付く
6. **プロフィールを整える**
   - 閲覧者が「新しいアカウント（作成72時間未満）」「メール未確認」「電話番号未認証」「デフォルトのプロフィール画像」を非表示にするフィルタを使っている場合、フォロー外のその人には表示されない
     （`visibility-filtering/rules/author_rules.rs:110-146`, `visibility-filtering/hydration/decode/author.rs:159`）
   - → **メール確認・電話番号認証・アイコン設定**は必ず済ませる

### 検索（ハッシュタグ検索）に出ない場合

検索結果の表示ルールそのものはこのリポジトリに**含まれていない**（visibility-filtering の判定レベルはホーム・おすすめ・通知だけ）。
ただし、検索向けとみられるラベルを付けるルールが2つある。ラベルを読む側（検索）のコードは非公開。

| ルール | 付くラベル | 条件 | 期間 |
| --- | --- | --- | --- |
| `botmaker-rules/scarecrow/bot/AgathaSpamProduction__ApplySearchTopTweetLabel.bot`（名前に SearchTopTweet） | 投稿に `AGATHA_SPAM` | アカウントの「スパム報告 ÷ いいね」スコアが 0.9975 超、または「スパムで凍結される可能性」の予測スコアが 0.98 超。条件を満たす間は**新しい投稿すべて**に付く | 各投稿 7 日 |
| `botmaker-rules/scarecrow/bot/Tweet_Search_Blacklist_RTF_All_UNSAFE_URL_Sources.bot` | 投稿に `SEARCH_BLACKLIST` / `DO_NOT_AMPLIFY` / `MALICIOUS_URL` | 危険（UNSAFE）判定のURLを含む | 期限なし |

- どちらも「信用スコアが高いアカウント」「政府認証アカウント」は対象外。新規アカウントは対象になる
- 確認するときは「話題」タブ（ランキングあり）ではなく「**最新**」タブで見る。ランキングで下がっただけの投稿は「最新」には出る
- 「最新」タブにも出ないなら、アカウント単位で検索から外されている可能性が高い。上の「避けること」を守って様子を見る

#### 切り分け手順（どこで外れているか）

| 検索 | 出る | 出ない |
| --- | --- | --- |
| `#ハッシュタグ`（最新タブ） | 「話題」タブの順位が低いだけ | ↓へ |
| `from:cassismilcrip`（最新タブ） | 投稿自体は検索対象。ハッシュタグ検索だけ外れている → 投稿単位のラベル（`AGATHA_SPAM` など）の可能性 | アカウント単位で検索から外れている |
| 投稿本文の一部を `"..."` で完全一致検索 | 同上 | 同上 |

記録欄:

| 日付 | 検索した人 | ハッシュタグ（最新） | from: | 完全一致 | メモ |
| --- | --- | --- | --- | --- | --- |
| | @kkk4oru | 出ない | | | |

ラベルが付いていたら、**原因になった行動をやめて有効期限（7〜30日）が過ぎるのを待つ**のが基本。
ラベルの有無を直接確かめる手段がないので、**3章の「避けること」を全部やめた状態で 30 日続ける**のが確実。
スパム系ラベルには異議申し立ての導線が用意されていない。

## 3. 切り抜きアカウントとして絶対に避けること

| やってはいけないこと | 理由（コード上） |
| --- | --- |
| **許可のない転載** | 著作権侵害の通報（DMCA）を受けると、投稿は全世界で非表示（`visibility-filtering/models/tweet.rs:102-118`, `visibility-filtering/rules/tweet_rules.rs:244-249`）。最優先で @_cassis_milk の切り抜きガイドラインを確認し、必要なら許可を取る |
| **毎回同じ本文テンプレート**（例：毎回同じ「【切り抜き】〇〇 #〇〇 #〇〇」） | ほぼ同一の本文をまとめて `COPYPASTA_SPAM` を付けるジョブがある。日本語用の文字単位版もある（`botmaker-rules/scarecrow/bot/BBQDuplicateTextProd.bot`） |
| **同じ文面の宣伝リプライ／フォロー外の人へのメンション＋リンク** | 重複文面のリプライ検出、低品質URL＋フォロー外メンションで `SPAM_HIGH_RECALL`（`LQ_Tweets_With_LQ_URL_Verdict_At_Mention_To_NonFollower.bot`） |
| **大きいスレッドへの宣伝リプライ** | LLM がスパム判定すると、そのリプライは 14 日間フォロー外から見えなくなる（`grox/flows/reply_spam/`, `GroxTweetProcessor.bot`） |
| **短縮URL・不明なドメインへのリンク** | リダイレクトの途中に1つでも低品質判定のURLがあればスパムラベル（`..._v2.bot`） |
| **機械的な行動**（1秒以内の連続操作、一定間隔の自動いいね・フォロー、フォロー＆リムーブ） | 行動系列からボットを検出するモデルがある（`bdsm/rust/abuse-v3-features/src/derived.rs`） |
| **ブロック・通報されやすい投稿** | フォロー外からのいいねに対するブロック・スパム報告の比率でアカウントにラベルが付く。新規アカウントは分母（いいね）が小さいので、数件の通報でも比率が跳ね上がる（`agatha/scalding/labels/rate_based_labels/RateBasedLabels.scala`） |

## 4. 伸ばすためにやること

### 4-1. 投稿は「オリジナル投稿」で、動画を直接アップする
- フォロー外の人のおすすめには、**リポスト・リプライは出ない**（`OONRetweetReplyFilter`）
- 新規作者ブースト（後述）も**オリジナル投稿のみ**が対象

### 4-2. 新規作者ブーストを活かす（投稿後 2 時間が勝負）
`home-mixer/scorers/author_cold_start.rs`, `home-mixer/params/param.rs:608-680`

- 条件: フォロワー **5万人以下**、投稿後 **2時間以内**、ホームでの表示 **200回未満**
- 選ばれた投稿は、閲覧者のおすすめで**15位相当まで引き上げられる**
- 選ばれる確率は「いいね数 ÷ 表示数」で決まる（Thompson サンプリング、事前分布 Beta(0.75, 49.25)）
- → **最初の表示で「いいね」されるかがすべて**。冒頭1〜2秒で掴む動画・サムネ・1行目にする
- → 1日に何本か、**時間をずらして**投稿すれば、ブーストの機会が投稿ごとに得られる

### 4-3. スコアの重み（何が効くか）
`home-mixer/params/param.rs:404-533`。重みは「閲覧者がその行動をとる**予測確率**」に掛かる（実際のいいね数に掛かるのではない）。

| 行動 | 重み | 示唆 |
| --- | --- | --- |
| リンクをコピーして共有 | **20.0** | 「友達に送りたくなる」名場面が最強 |
| リプライ / 引用 / DM で共有 | **5.0** | 会話が生まれる一言を添える（「このシーン何回見ても笑う」など） |
| 作者をフォロー | 4.0 | プロフィールを見て「フォローしたくなる」一貫性を出す |
| 共有 | 2.1 | |
| リポスト | 1.0 | |
| いいね | 0.7 | |
| 興味がない | **-53.1** | 釣りタイトル・期待外れの内容は大きく減点 |
| ミュート | **-58.8** | 投稿しすぎ・同じ内容の連投は避ける |
| ブロック | -31.2 | |
| 通報 | **-234.0** | 無断転載・センシティブな場面の切り抜きは避ける |

### 4-4. 最後まで見られる動画にする
- 2026年10月の更新で、**滞在時間の予測**と**最後まで見られた投稿**の推薦が強化された（`phoenix/xrex/models/recsys_model.py`, `phoenix/xrex/configs/xrecsys_two_tower.py`）
- すぐスクロールされると減点（not dwelled）
- → **短く、オチまで見たくなる構成**にする。前置きは削る

### 4-4b. 動画は縦型（幅 < 高さ）を基本にする

- おすすめ（For You）のフィード内に、動画を3〜5本並べる「動画カルーセル」がある。対象は**縦動画だけ**（幅÷高さ < 1.0。正方形1:1と横動画は対象外）（`home-mixer/util/video_carousel.rs:14, 97, 214-218`）
  - 並び順は「動画を開きそうか」「どれだけ見続けそうか」の予測で決まる
  - 1作者1本まで。メインのフィードにすでに出ている動画や、似た動画（埋め込みの類似度 0.72 以上）は除外される
  - リプライの動画は対象外
  - リポジトリ上の初期値は無効（`EnableVideoCarousel = false`）。本番で有効かは設定次第で、コードからは分からない
- 通常のおすすめの順位付けにアスペクト比は使われていない（モデルへの入力は「動画があるか」「長さ」など）
- → 縦動画にすると、通常のおすすめ枠に加えて**カルーセル枠にも入る可能性がある**。横動画にしても通常枠で不利にはならない
- 縦動画は TikTok / Instagram リール / YouTube ショートにもそのまま使い回せる

### 4-4c. 字幕は「焼き込み」にする（SRT は判定に使われない）

- 投稿の内容を理解する埋め込みモデル（`grox/flows/mm_emb/renderer_v8_search.py`）が動画から読むのは次の3つ
  - 動画から**等間隔に抜き出した最大4フレームの画像**（`max_frames = 4`）
  - **自動音声認識（ASR）の文字起こし**（`asr_transcript`）
  - 投稿の本文
- アップロードした SRT 字幕ファイルを読むコードは見当たらない
- → 画面に**焼き込んだ字幕**はフレーム画像に写るので、モデルが内容を読み取れる。歌や BGM が多い動画は ASR の精度が落ちやすいので特に効く
- 4フレームは等間隔に抜かれるので、字幕は冒頭だけでなく**最初から最後まで**入れる
- この埋め込みは名前から検索向けで、動画カルーセルの重複除外・クリック予測にも同じ版（`v8_search_1`）が使われる（`home-mixer/params/param.rs` の `VideoCarouselEmbeddingVersion`）
- 音を出さずに見る人にも内容が伝わり、離脱を減らせる（滞在時間・最後まで見られたかは評価対象）

### 4-5. 投稿間隔をあける
- 同じ作者の投稿は、同じ閲覧者のタイムライン内で 2本目×0.625、3本目×0.4375…と減衰し、最小で×0.25（`vm-ranker/params.rs:175-192`）
- フォロー外の投稿はもともと×0.75
- 投稿は48時間を過ぎるとおすすめの候補から外れる（`home-mixer/params/config.rs:39`）
- → 連投より、**1日数本を時間をずらして**、毎日続けるほうが有利

### 4-5b. 1日に複数本投稿するときの間隔と時間帯

- **間隔の目安（コードから言えること／言えないこと）**
  - コードで確認できる事実
    - 新規作者ブーストは、閲覧者がフィードを読み込むたびに、条件を満たす**全アカウントの投稿の中から1本だけ**選ばれる（`home-mixer/scorers/author_cold_start.rs:296-331`）。条件は投稿ごとに判定され、「投稿後2時間以内」も**各投稿の投稿時刻から**数える
    - 1回の読み込みの候補の中に同じ作者の投稿が複数あると、スコア順で2本目×0.625、3本目×0.4375…（最小×0.25）になる（`xai-value-model/scoring.rs:261-280`, `vm-ranker/params.rs:175-192`）。「隣に並ぶ」ではなく「同じ読み込みの候補に入る」と下がる
    - その閲覧者に表示済みの投稿は候補から外れる（`home-mixer/filters/previously_seen_posts_filter.rs`）
  - コードからは言えないこと（推測・経験則）
    - 「2時間以内に2本出すとブースト枠を自分同士で取り合う」とは言い切れない。枠は全アカウント共通の1本で、競争相手は主に他の作者。2本同時に条件を満たしていても、自分のどちらかが選ばれる確率が下がるとは限らない
    - 「4〜5時間」「1日3本」はコード上の数値ではなく、上の減衰（同じ読み込みに入ると下がる）と、連投によるミュート・「興味がない」を避けるための経験則
  - → 間隔をあけるほど、同じ閲覧者の同じ読み込みに2本入りにくくなる。具体的な時間は `analytics/` の数値で検証する
- **時間帯（コード外の一般的なデータ）**
  - 総務省の調査では、休日のネット利用は 9時台〜23時台まで大きな差がなく、21時台がやや高い
  - → 週末は「午前遅め（11時前後）」「夕方（16〜17時）」「夜（20〜22時）」に分散させる
  - @_cassis_milk の**配信と重ならない時間**にする（ファンが配信を見ている間は X を見ない）。配信終了直後は関連の切り抜きが見られやすい
  - 最適な時間はアカウントごとに違うので、投稿ごとの 2 時間後の数値を記録して比較する

### 4-6. 刺さる層の「いいね」を集める
- SimClusters（フォロー外への推薦経路の一つ）は「誰にいいねされたか」で投稿の位置づけを決める（`home-mixer/sources/simclusters_source.rs`）
- → @_cassis_milk のファン層にいいねされると、同じ興味の人へ広がりやすい
- ハッシュタグがランキングに効くロジックはコードに見当たらない。付けすぎず、検索用に最小限にする

### 4-6b. @_cassis_milk にリポストしてもらうときの仕組み

コードで確認できる事実:
- リポストは**リポストした人（@_cassis_milk）の投稿**として扱われる。作者IDは @_cassis_milk、元の作者は別の項目に入る（`home-mixer/models/candidate.rs:278-284`）
- 「48時間以内」はリポストした時刻から数える（`home-mixer/filters/age_filter.rs` はリポスト自体の投稿IDで判定）。元の切り抜きが古くても、リポストから48時間はおすすめ候補に入れる
- フォローしていない人のおすすめには、リポストは出ない（`OONRetweetReplyFilter`）。届くのは **@_cassis_milk のフォロワー**
- フォロー中の人のリポストにも×0.75の割引がかかる（`vm-ranker/params.rs` の `EnableOonRescoreForInNetworkRepliesRetweets = true`）
- 作者の多様性による減衰は作者ID単位で計算される（`xai-value-model/scoring.rs:300-303`）。同じ閲覧者の同じ読み込みに **@_cassis_milk 本人の投稿**（配信告知・本人の動画）が候補として入っていて、そちらのスコアが高いと、リポストは2本目以降として×0.625以下になる
- 元の切り抜きとリポストは同じ投稿として1本にまとめられる。どちらかを見た人には、もう片方は出ない（`retweet_deduplication_filter.rs`, `previously_seen_posts_filter.rs`）
- 新規作者ブーストはリポストには適用されない（オリジナル投稿のみ）

ここから考えられること（推測）:
- 本人の告知や本人の動画の直後にリポストされると、同じ読み込みに入って減衰しやすい。本人の投稿から時間が空いたタイミングでリポストしてもらうほうが有利な可能性がある
- 切り抜きの投稿時刻と、本人がリポストする時刻は別。リポストする時刻のほうが重要

### 4-6c. ツリーのリンク投稿・アカウントのタグ付け

ツリー（自分の投稿へのリプライ）に URL を書く場合:
- 本文の「長さ」の特徴量は URL 部分を数えない（`home-mixer/models/content_features.rs`）。URL だけだと長さはほぼ 0、「外部リンクあり」だけが立つ
- リプライはフォロー外のおすすめに出ないので、リプライ自体の順位への影響は小さい。本体の投稿の評価には影響しない（特徴量は投稿ごと）
- 毎回「URL だけ」「同じ定型文＋URL」だと、同じ文面の検出（`BBQDuplicateTextRepliesProd.bot`）に引っかかる可能性がある（URL の扱いは非公開）
- → **配信タイトル・日付・場面などの一言を毎回変えて添える**

動画・画像へのアカウントのタグ付け／本文でのメンション:
- おすすめの順位付けで、メンションやメディアのタグを使う処理は見当たらない（加点も減点もない）
- 効くのは**相手への通知**。通知のフィルタは種類で違う（`visibility-filtering/rules/levels.rs`）
  - メンション・リプライの通知: 投稿に低品質・スパム・重複メンションなどのラベルがあると相手に届かない
  - メディアのタグ付けの通知: 投稿ラベルによる除外がほとんどない（相手の「フォローしている人のみ」設定は効く）
  - どちらも、作者アカウントのラベル（新規・スパム系など）があると、相手がフォローしていない場合は届かない
- → @_cassis_milk に確実に気づいてもらうなら、本人にフォローしてもらった上でタグ付けかメンションをする
- 関係ない人をタグ付け・メンションしない（通報・ブロックの原因になる）

### 4-7. アカウントの信用スコアを上げる（user-cred）
`user-cred-v2/`

- フォローグラフ上の PageRank でアカウントの信用度を算出している
- **信用度の高いアカウントからのフォロー・いいね・リポスト**で上がる
- X Premium のアカウントは初期配分を受けられる
- スコアが54以上になると、重複本文などの自動スパムルールの対象外になる（`botmaker-rules/scarecrow/derived-feature/HighPageRankThreshold.df`）
- → 本人や関係者のアカウントとの自然なつながり、Premium 加入は効果がある。ただし相互いいね集団のような組織的な水増しは、ボット検出の対象（EngagementAmplifier）
